# G-VAMP

**Official implementation of G-VAMP**, the method presented in:

> Santiago Fernández Lanza, Víctor Manuel Darriba Bilbao, and Daniel Fernández-González.
> **G-VAMP: Improving Sequence Labelling Frameworks for Multiword Expressions Identification.**
> *Array*, accepted for publication.

G-VAMP is a method for improving the identification of **verbal multiword expressions (VMWEs) with shared tokens** using sequence-labelling models.

The method was developed in the context of the [PARSEME](https://parsemefr.lis-lab.fr/) shared task corpora and addresses one of the limitations of conventional sequence-labelling approaches: a token can normally receive only one label, whereas different VMWEs may share one or more tokens.

G-VAMP tackles this problem by generating multiple variants of the training corpus in which conflicting VMWEs are distributed across different versions. An independent sequence-labelling model is trained on each variant, and their predictions are subsequently merged to recover VMWEs that may share tokens.

## Overview

Given a training corpus containing VMWEs with shared tokens, G-VAMP performs the following main steps:

1. **Corpus splitting**
   The original training corpus is transformed into several variants so that VMWEs with shared tokens can be represented independently.

2. **Sequence labelling**
   The resulting training variants, together with the development and test sets, are converted into a sequence-labelling representation.

3. **Model training and prediction**
   An independent token-classification model is trained on each training variant.

4. **Prediction merging**
   The predictions obtained from the different models are combined.

5. **Post-processing**
   The merged predictions are converted back into PARSEME CUPT format, allowing the reconstruction of VMWEs with shared tokens.

6. **Evaluation**
   The resulting system predictions are evaluated using the official PARSEME evaluation scripts.

## Supported labelling schemes

The current implementation supports the following sequence-labelling schemes:

* `IOB`
* `IOB_Deep-BGT`
* `gappy-1_Deep-BGT`
* `gappy-crossy_Deep-BGT`

The labelling scheme can be independently selected for the training, development and test sets in `do_experiment_lan.sh`.

## G-VAMP strategy for shared tokens

G-VAMP uses the `SPLIT&MERGE_OVL` strategy implemented in the preprocessing code.

This strategy analyses the overlapping structure of VMWEs in the training corpus and generates the training variants required to represent expressions that share tokens. Each variant is subsequently used to train an independent sequence-labelling model. The predictions produced by these models are finally merged to reconstruct the VMWEs, including those involving shared tokens.

```
    ├── summarizer.py
    ├── tools.py

```

The directories `corpus/`, `evaluations/` and `models/` are initially empty and are used as follows:

* `corpus/` contains the PARSEME corpora used for training, development and evaluation.
* `evaluations/` stores the outputs and evaluation results generated by the experiments.
* `models/` can contain language-specific pretrained models. If no language-specific model is provided, the default multilingual model is used.
* `transformers/` is created by cloning the Hugging Face Transformers repository, as explained below.

### `do_experiment_lan.sh`

Runs the complete G-VAMP experimental pipeline for a single language, including preprocessing, model training with three random seeds, prediction merging, post-processing and evaluation.

### `do_experiment_all.sh`

Runs `do_experiment_lan.sh` for all languages available for a given corpus version.

### `preprocess.sh`

Calls the preprocessing pipeline implemented in `source/preprocess.py`.

The preprocessing stage:

1. generates the training variants required by G-VAMP;
2. applies the selected sequence-labelling scheme; and
3. converts the resulting data into JSON format for Hugging Face token classification.

### `process.sh`

Runs the Hugging Face token-classification model for a given training variant and random seed.

### `source/postprocess.py`

Merges the predictions obtained from the different training variants and converts them back into CUPT format.

## Data organisation

The `corpus/` directory is initially empty. PARSEME corpora must be downloaded separately and placed in this directory before running the experiments.

Corpora are expected to follow this directory structure:

```
corpus/
└── <CORPUS_VERSION>/
    └── <LANGUAGE>/
        ├── train.cupt
        ├── dev.cupt
        └── test.cupt
```

For example:

```
corpus/
└── 1.3/
    ├── EN/
    │   ├── train.cupt
    │   ├── dev.cupt
    │   └── test.cupt
    ├── ES/
    │   ├── train.cupt
    │   ├── dev.cupt
    │   └── test.cupt
    └── ...
```

If `test.blind.cupt` is not available, the post-processing code automatically generates it from `test.cupt`.

The experiments reported in the G-VAMP paper were conducted on the **PARSEME 1.3** corpora.

## Hugging Face Transformers

This repository uses the token-classification implementation provided by Hugging Face Transformers.

The `transformers/` directory is not included in this repository. To reproduce the environment used in the G-VAMP experiments, clone the Hugging Face Transformers repository and check out version `v4.52.0.dev0`:

```bash
git clone https://github.com/huggingface/transformers.git
cd transformers
git checkout v4.52.0.dev0
pip install -e .
cd examples/pytorch/token-classification/
pip install -r requirements.txt
```

These commands create the following directory structure inside the G-VAMP repository:

```
G-VAMP/
└── transformers/
    └── examples/
        └── pytorch/
            └── token-classification/
                └── run_ner.py
```

The `process.sh` script executes the Hugging Face token-classification example located at:

```
transformers/examples/pytorch/token-classification/run_ner.py
```

Using the specified Transformers version is recommended for reproducing the experiments reported in the paper.

## Model configuration

By default, the experiments use:

```
google-bert/bert-base-multilingual-cased
```

The main experimental configuration in `do_experiment_lan.sh` is:

```
Model: google-bert/bert-base-multilingual-cased
Epochs: 15
Seeds: 1, 2, 3
Shared-token strategy: SPLIT&MERGE_OVL
```

The best model is selected according to the F1 score on the development set.

Language-specific models can optionally be placed under:

```
models/<LANGUAGE>/
```

If a model is found in this directory, the script uses it instead of the default multilingual BERT model.

The code requires:

* Python 3

The required Hugging Face dependencies for token classification are installed through:

```bash
pip install -r transformers/examples/pytorch/token-classification/requirements.txt
```

## PARSEME evaluation scripts

The official PARSEME evaluation scripts are **not included in this repository**, as they are part of the PARSEME resources.

G-VAMP expects the corresponding evaluation script to be available at:

```
source/<CORPUS_VERSION>/evaluate.sh
```

For PARSEME 1.3, for example:

```
source/1.3/evaluate.sh
```

Before running an experiment, download the official evaluation scripts corresponding to the PARSEME corpus version being used and place them in the appropriate directory.

The evaluation scripts can be obtained from the official PARSEME resources.

## Running an experiment

Before running G-VAMP:

1. Download the required PARSEME corpora and place them under `corpus/`.
2. Clone and install Hugging Face Transformers as described above.
3. Download the official PARSEME evaluation scripts and place them under `source/<CORPUS_VERSION>/`.
4. Make sure that all required Python dependencies are installed.

To run G-VAMP for a single language:

```bash
./do_experiment_lan.sh <CORPUS_VERSION> <LANGUAGE>
```

For example:

```bash
./do_experiment_lan.sh 1.3 ES
```

This command performs the complete pipeline for Spanish.

To run the experiments for all languages contained in a corpus version:

```bash
./do_experiment_all.sh <CORPUS_VERSION>
```

For example:

```bash
./do_experiment_all.sh 1.3
```

## Experimental pipeline

For each language, `do_experiment_lan.sh` first preprocesses the corpus:

```bash
./preprocess.sh $CORPUS_VERSION $LAN $TRAIN $DEV $TEST $METHOD_FOR_SHARED
```

With `SPLIT&MERGE_OVL`, the training set is divided into multiple variants according to the shared-token structure of its VMWEs.

A separate model is then trained for every generated training variant and for each of the three random seeds:

```
1
2
3
```

After prediction, the outputs from the different variants are merged:

```bash
python3 source/postprocess.py \
    <corpus_folder> \
    <predictions_folder> \
    <shared_token_method>
```

The final predictions are written in CUPT format and evaluated against the gold-standard test data.

## Output

Each experiment creates a timestamped directory under:

```
evaluations/
```

with a structure similar to:

```
evaluations/
└── <TIMESTAMP>-<CORPUS_VERSION>-<LANGUAGE>/
    ├── 1/
    │   ├── predictions/
    │   └── postprocess/
    ├── 2/
    │   ├── predictions/
    │   └── postprocess/
    ├── 3/
    │   ├── predictions/
    │   └── postprocess/
    ├── eval_1.txt
    ├── eval_2.txt
    ├── eval_3.txt
    ├── README_evaluations.txt
    └── evaluations.tsv
```

The results obtained with the three random seeds are summarised automatically in `README_evaluations.txt` and `evaluations.tsv`.

## Evaluation

Evaluation is performed using the official PARSEME evaluation scripts. The system-generated CUPT file is compared with the corresponding gold-standard test set.

The evaluation reports MWE-based precision, recall and F1 scores.
